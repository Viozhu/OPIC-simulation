# The exam in a browser — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the exam screens tell the candidate what is happening — the
microphone is heard, the progress is visible, the report is the good one — and
make a screen reader and a dark-mode browser first-class.

**Architecture:** Nine tasks, front-loaded with the Python ones so the browser
work lands on an endpoint that already exists and is tested. Tasks 1–3 are
covered by pytest. Tasks 4–9 are JavaScript and CSS in a codebase with no test
runner and no build step, so each one carries an explicit browser check against
a real graded session on disk instead.

**Tech Stack:** FastAPI, plain ES modules served raw, no bundler, pytest.

**Spec:** `docs/superpowers/specs/2026-08-24-web-ux-design.md`

## Global Constraints

- The UI speaks Korean. Every user-visible string added here is Korean.
- No build step, no bundler, no npm. ES modules are served as written.
- No new runtime dependency, Python or JavaScript.
- `core/` stays pure: no I/O, no network, no `datetime.now`. `tests/test_core_purity.py`
  enforces this and already lists `page.py` and `narrative.py`.
- Target browsers: Chrome and Safari on desktop. Phone layouts are out of scope.
- The meter is decoration on a critical path. Nothing in it may raise into a
  recording path.
- Every commit leaves `uv run pytest` green.

## Prerequisite

The phase-5 work in the working tree (`core/page.py`, `core/narrative.py`,

```python
def html_for(root: Path, session_id: str) -> str | None:
    """The report page for a session: the written file, or one rendered now.

    The file on disk is the better answer whenever it is there — it is the one
    the worker rendered with a narrative, and that narrative cost a model call
    that a page view has no business paying again. Rendering on demand covers
    the session graded before this file existed and the one whose narrative
    call failed: the same page, minus the judged sections.

    `None` when there is nothing to render at all — no `result.json`, or not
    one readable answer file. The web layer turns that into a 404.

    Reading never writes. A GET that leaves a file behind is a GET that can
    fail in ways a reader cannot see.
    """
    written = store.page_path(root, session_id)
    if written.exists():
        try:
            return written.read_text(encoding="utf-8")
        except OSError:
            # An unreadable page is not a reason to have no page: everything
            # it was built from is still sitting next to it.
            traceback.print_exc()
    built = build(root, session_id)
    if built is None:
        return None
    report, meta = built
    return render_html(report, meta, None)
```

```js
// The report: rendered by `core/page.py`, served whole by
// `/api/sessions/{id}/page`, and shown here inside a frame. This screen used
// to draw the report itself, worse than the page did — two renderers of one
// model, and the browser got the poorer one.
//
// What survives from that version is the fallback ladder underneath, rung for
// rung: no page but a `result.json` still shows a level (`renderMinimal`), and
// neither shows the retry screen (`renderRetry`). The top rung is the only one
// that changed.
export async function render(state, {api}) {
  const app = document.getElementById("app");
  await load(app, state, api);
}

async function load(app, state, api) {
  const url = `/api/sessions/${state.id}/page`;
  if (await pageExists(url)) {
    renderFrame(app, url);
    return;
  }
  // No rendered page. `result.json` may still be there — it is written before
  // the page and by a path that cannot fail the same way.
  let raw = null;
  try {
    raw = await api.get(`/api/sessions/${state.id}/result`);
  } catch (error) {
    renderRetry(app, state, api);
    return;
  }
  renderMinimal(app, raw);
}

// A HEAD before the iframe: framing the URL blind would put a JSON 404 body
// on screen where a report should be, and an iframe gives no usable way to
// notice that after the fact.
async function pageExists(url) {
  try {
    const response = await fetch(url, {method: "HEAD"});
    return response.ok;
  } catch (error) {
    return false;
  }
}

function renderFrame(app, url) {
  const frame = document.createElement("iframe");
  frame.className = "report-frame";
  frame.src = url;
  frame.title = "OPIc 리포트";

  const open = document.createElement("a");
  open.href = url;
  open.target = "_blank";
  open.rel = "noopener";
  open.className = "report-open";
  open.textContent = "새 탭에서 열기 (인쇄·저장)";

  const actions = document.createElement("p");
  actions.className = "actions";
  actions.append(open, restartButton());

  app.replaceChildren(frame, actions);
}
```

- [ ] **Step 1: Write `meter.js`**

```js
// The level bar: proof, while recording, that something is being heard.
//
// Decoration on a critical path. Every branch here is wrapped and every
// failure returns a meter that draws nothing, because a browser that will not
// hand over an AudioContext must cost the candidate a bar and not an exam.

// The RMS peak below which a recording is treated as silence. Chosen, not
// measured: well under speech, well over the noise floor of a laptop
// microphone in a quiet room. Only the setup step acts on it, and only by
// warning — see steps/setup.js.
export const SILENCE_PEAK = 0.02;

// A full bar at this RMS. Speech rarely goes past it, and a bar that only ever
// moves in its bottom tenth reads as broken.
const FULL_SCALE = 0.2;

const DEAF = {element: null, peak: () => null, stop: () => {}};

export function levelMeter(stream) {
  let context = null;
  try {
    const Context = window.AudioContext ?? window.webkitAudioContext;
    if (!Context) return DEAF;
    context = new Context();
    const analyser = context.createAnalyser();
    analyser.fftSize = 1024;
    context.createMediaStreamSource(stream).connect(analyser);

    const element = document.createElement("div");
    element.className = "meter";
    // The status line and the clock next to it already say what is happening;
    // a bar that announces a number many times a second would only get in the
    // way of a screen reader.
    element.setAttribute("aria-hidden", "true");
    const fill = document.createElement("span");
    fill.className = "meter__fill";
    element.append(fill);

    // The byte view, not the float one: it is the older API and the one every
    // target browser has had for years.
    const samples = new Uint8Array(analyser.fftSize);
    let peak = 0;
    let running = true;

    const tick = () => {
      if (!running) return;
      analyser.getByteTimeDomainData(samples);
      let sum = 0;
      for (const sample of samples) {
        const centred = (sample - 128) / 128;
        sum += centred * centred;
      }
      const rms = Math.sqrt(sum / samples.length);
      if (rms > peak) peak = rms;
      fill.style.width = `${Math.min(100, (rms / FULL_SCALE) * 100)}%`;
      requestAnimationFrame(tick);
    };
    requestAnimationFrame(tick);

    return {
      element,
      peak: () => peak,
      stop() {
        running = false;
        try {
          context.close();
        } catch (error) {
          // A context that will not close is not worth a broken screen.
        }
      },
    };
  } catch (error) {
    // The console keeps the real cause for whoever debugs this; the candidate
    // gets a screen that behaves exactly as it did before there was a meter.
    console.error(error);
    try {
      context?.close();
    } catch (ignored) {}
    return DEAF;
  }
}
```

Note the `peak()` contract: `DEAF` returns `null`, a live meter returns a
number. `null` means "not measured" and callers must never read it as silence.
